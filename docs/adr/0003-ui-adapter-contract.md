# ADR 0003 — Behavioral UI contract through caller-bound capabilities

Status: **Proposed for review**, 2026-09-19. Author: Stanley, Architect. Card: H101-40. No implementation or new phase approval. Kelly owns the executable exit criteria under H101-39; this document defines their shared contract, not a second CI checklist.

## Context and inspected evidence

**SECONDARY SOURCE.** [Phase 2 in the plan](../PROJECT-PLAN.md) requires a CLI and a throwaway second adapter to demonstrate replacement. [Boundaries](../architecture/boundaries.md) already require commands, queries, state observation, and a separate output stream. [Phase 1's milestone](../PHASE-1-MILESTONE.md) limits the trust claim and leaves crash-lock recovery and mailbox integration outstanding.

**CODE-PATH FACT.** The inspected `internal/host/host.go` returns an unexported workspace through Capabilities. It privately constructs storage, copies the reviewer set, and detaches query records. However, every user command accepts a callerAgentID; the same interface includes RecordMessagePublished, RecordMessageProcessed, and Close. Queries expose only individual agent/task/message records, not a snapshot or the TaskResult summary/artifacts/decision. There is no subscription, run-output, or supported-capability query on that returned interface. These are working-tree observations, not independent verification of the dispatch's `36021c3` revision.

**CODE-PATH FACT.** The current import gate checks direct production imports of statestore and the combined ports package. Its configuration does not restrict imports of host or core/task; test imports are excluded. Thus it does not currently stop a UI from calling host.Open, naming task.CallerScope, or importing the engine package. An unexported workspace type does not hide its exported methods from a matching interface assertion.

## Options and decision

**INFERENCE.** Passing today's Capabilities to both adapters would prove common API consumption, but leave callers able to select another identity, fabricate delivery facts, or close a shared session. A narrower interface assigned over that same concrete value is insufficient: its extra exported methods remain recoverable by interface assertion. Duplicating a service for each adapter would instead introduce divergent policy and two persistence owners.

**INFERENCE — proposed decision.** Keep one trusted composition owner and the existing core/storage transaction design. Before exposing the complete CLI command set, add a genuinely separate, unexported **FrontendSession** wrapper bound to one host-established principal. It delegates permitted calls and never embeds the broad Capabilities object. Each principal may have multiple UI sessions; two adapters use the same application behavior through separate session objects. Keep ten architectural ports; refine capability distribution rather than adding a persistence door. This is a durable public-contract constraint, hence an ADR.

**INFERENCE — authority ownership.** Only the reviewed executable assembly chooses the workspace, reviewer policy, and session principal from operator configuration. Agent message payloads, task fields, and adapter interaction input cannot select or expand that authority. The UI receives no caller-ID parameter or reviewer-set constructor. A claimed message sender remains message data, not session authority. Switching principals requires assembly to issue another session. This constrains application code, not a malicious program or same-user impersonation; origin stays unverified under ADR 0002.

## Session surface and implementation cost

**INFERENCE.** Define an inbound-only contract package, proposed `internal/api`, containing frontend interfaces, command data-transfer records, and stable result/error types. It must not expose StateStore, CommitRequest, CallerScope, Engine, host constructors, or filesystem objects. Move or alias the existing command records into this neutral package with dependency direction chosen to avoid cycles; frontend adapters must not need to import core/task merely to name request types. Do not alias privileged engine/authority types. Core/domain records may be reused as detached values.

**INFERENCE.** FrontendSession provides the existing nine user commands without callerAgentID; detached GetAgent/GetTask/GetMessage; GetSnapshot with workspace revision and agents, tasks, results, messages and provenance; GetCapabilities; and state subscription using the cursor semantics below. Existing TaskResult data can therefore be inspected without reading state.json. Delivery recording belongs to a separate mailbox capability supplied only to the trusted integration. Close belongs to the assembly's lifecycle handle. A session's detach/cancellation releases its subscriptions, not the workspace. Lifecycle access is never passed to presentation code.

**INFERENCE — enumeration ruling (H101-40 amendment).** Get-by-ID alone is insufficient. The required operation is `FrontendSession.GetSnapshot(ctx)`: workspace selection is already bound to the session, so the UI supplies no path or alternate workspace ID. Return a versioned detached WorkspaceView containing `workspaceID`, `revision`, `cursor`, and complete collections `agents`, `tasks`, `taskResults`, and `messages`. Each collection includes its domain IDs and the same fields/provenance available through record queries, including result summaries, artifact references, decisions, and all four message-delivery facts. The host may adapt the already-declared `Queries.GetSnapshot(ctx, workspaceID)` internally; the UI must not import the combined ports package to obtain it. The view contains no receipt ledger, reviewer configuration, store handles, execution credentials, or callbacks.

**INFERENCE — completeness and consistency.** Every collection reflects one committed workspace revision; an empty workspace returns explicit empty collections, not NotFound. The accompanying cursor denotes that same committed cut for subscription replay. Version 1 returns a complete snapshot without pagination or silent truncation; order is unspecified and adapters may sort for display. A read failure returns an error, not a partial view labelled complete. If scale requires pagination later, introduce a snapshot-bound continuation contract before claiming complete enumeration; iterating pages from changing revisions is not an equivalent replacement. Snapshot visibility is workspace-wide in the current single-user design, not a new per-agent confidentiality boundary.

**INFERENCE — detachment and discovery proof.** Deep-copy every reachable slice, map, pointer and nested record, including TaskResult artifact slices, CurrentResultID, provenance pointers and message timestamps. No object in the returned graph may alias host/engine/store-owned mutable state or a later query result. Updating the workspace after the read must likewise leave that old view unchanged. The shared suite must begin an overview interaction without injecting existing entity IDs into either driver, discover the fixture's records through that adapter, and then inspect one returned ID. Include an empty-workspace view and a mutation probe against nested returned data followed by fresh query and reopen; persisted state must be unchanged. This makes enumeration and detachment observable parts of UI-06/UI-08 rather than merely adding a method name.

**INFERENCE.** This costs host wrappers, inbound-record/interface extraction, missing query/observation plumbing, and integration tests; task transition logic and Commit need no rewrite. GetSnapshot and StateEvents are already requirements in boundaries.md, not newly invented GUI features. They are not implemented by today's facade and must not be claimed as demonstrated yet. Start/Stop/Budget and actual run output remain Phase 3: advertise them unavailable and report Unsupported for attempts rather than showing fake successful state. Tests of a fake output stream demonstrate adapter behavior only, not agent supervision.

## Shared behavioral contract

**INFERENCE.** Assign these stable identifiers to scenarios; Kelly maps them to CI commands, fixtures and milestone assertions. Each adapter must enter through its real parser/input handler and render its real response. A test wrapper that calls host commands instead of the adapter's production path is not a second adapter.

| ID | Behavior required from every adapter |
| --- | --- |
| UI-01 | Translate explicit intent into one matching command with unchanged IDs, task revisions, body text and references. Reject malformed input without mutation. Do not infer acknowledgement, acceptance, or authority from display activity. |
| UI-02 | Present durable receipt versus completed work distinctly. Preserve stable domain error codes; never turn Denied/Conflict/IOFailure/OutcomeUncertain into success. Apply ADR 0004: retain original request identity and structured uncertainty semantics, explain Applied versus Unknown and missing confirmation, and never infer rollback from an error. An unclassified mutation IOFailure remains conservatively unconfirmed; read failures remain errors. |
| UI-03 | Preserve a caller-supplied request ID on retry. Same command retry produces the original receipt; changed payload conflicts. No automatic new-ID retry of an uncertain mutation. Generated IDs must be surfaced so an interrupted caller can recover them. |
| UI-04 | Complete registry, task, blocker, linked-message, acknowledgement, result-report, rejection/rework, and human-acceptance interactions with identical domain outcomes. AwaitingReview is never rendered as accepted Done. Wrong-principal operations retain the core's rejection. |
| UI-05 | Expose required provenance, result evidence, and separate queued/published/processed/acknowledged facts, including absent facts. Preserve unverified identity and ADR 0002's unconditional manual-agent disclosure. No validation-looking badge on manually sourced content. |
| UI-06 | Enumerate a workspace without prior entity IDs through a complete detached snapshot, then observe from its cursor without losing intervening commits. Preserve event ordering/IDs, deduplicate replays, and reload on CursorExpired. A snapshot refresh may coalesce views but must not be represented as a complete event history. |
| UI-07 | Detaching an observer or replacing a UI neither closes another session nor cancels accepted work. Graceful host reopen retains records and request-replay behavior. Crash restart is a separate inherited recovery obligation, not proven by graceful reopen. |
| UI-08 | Return detached values; editing a displayed/local record cannot mutate storage. Advertise unsupported operations consistently. Keep process output separate from domain events; stream cancellation detaches only the reader. |

**INFERENCE — stream semantics.** StateEvents retain the existing versioned envelope/cursor contract and bounded queues. A slow observer gets an explicit resumable disconnect; it cannot block commits indefinitely. Resume and cursor expiry have observable results. Supporting this requires real host/core replay plumbing; fabricated events reconstructed from a UI's own last command are invalid because they miss changes made through the other adapter. A headless observer can drive the same subscription used by both frontends. RunOutput contract tests can use a deterministic stream double until Phase 3, clearly separated from the real-host replacement verdict.

## One suite, independent adapters, and comparison

**INFERENCE.** Put the external black-box suite in `internal/adaptercontract/contract_test.go` (`adaptercontract_test`), with helper/driver code confined to `_test.go` files. The suite imports both adapters, the inbound contract, and host as the sole composition entry point. It never imports storage/outbound ports or parses state.json. It calls Open only to construct isolated real workspaces and obtains observations through frontend capabilities. No production allowlist entry is required under today's gate: test imports are excluded, and host is not a protected target. That exclusion is not permission for raw storage in these tests; extend architecture checks to enforce this suite's declared dependency set.

**INFERENCE.** Each test driver supplies Bind(session), Invoke(interaction), Observe(cursor), and Detach. A CLI driver serializes interaction into actual arguments/stdin and parses the CLI's documented structured output; the throwaway driver uses an independent input representation/handler. The throwaway cannot import the CLI, reuse its parser/dispatcher, or bypass its own handler to invoke the host. Shared inbound record types are allowed; shared UI dispatch is not evidence of replacement. Runner lifecycle and trusted principal setup remain harness responsibilities, never test-interaction fields.

**INFERENCE.** Run the same scenario against separate fresh workspaces for each adapter, then run a crossover scenario: adapter A writes/reports, detach A, adapter B reads/acknowledges/reviews through a separately bound principal, and reopen through the opposite adapter. Domain state must be shared without import/export conversion or core changes. A concurrent observer scenario proves changes originating outside an adapter are visible to it.

**INFERENCE — canonical observations.** Compare command outcomes (request ID, receipt revision, error code), snapshot contents, result/decision records, message facts, provenance, and ordered event kind/subjects/revisions. Sort unordered collections by domain ID. Keep user-supplied IDs and text exact. Normalize only nondeterministic generated event IDs by a bijection preserving repeats/order, and timestamps by structural assertions for presence, immutability and causal relationships; do not erase timestamps or substitute one adapter's output as the expected answer. Assert each against independently specified expected states as well as against the other, so two adapters making the same mistake cannot pass by equality alone. Rendering differs; semantic facts cannot. CLI help/exit-code formatting remains adapter-specific testing owned by Kelly.

## Prohibitions and limits

**INFERENCE.** Structurally remove mutation/authority/lifecycle methods from the actual session wrapper, not just its static interface. Enforce a UI import allowlist permitting inbound contracts/domain but rejecting host, core/task, concrete I/O adapters and outbound ports; only executable assembly imports host. The current check must be expanded to enforce this role split—no storage/ports exception is added for UI packages. Public request types must not include reviewer authority. Presentation receives injected readers/writers rather than raw workspace paths or environment-based reviewer configuration.

**INFERENCE.** Go types do not prevent arbitrary code importing os or making network calls. Dependency checks, command-path integration tests, and reviewed assembly therefore remain necessary; do not label these behaviors structurally impossible. Persisting receipts, writing a second ledger, shelling out to the CLI from the throwaway adapter, automatic retries with new IDs, and reading task files to choose reviewer policy are forbidden. Keeping core behavior unchanged when the second adapter is added is the final dependency test, not an assertion the compiler can make today.

## H101-70 clarification — observation lifetime (2026-09-21)

**INFERENCE — scope ruling.** The concurrent-observer scenario requires separate adapters/sessions observing one authoritative host/engine, not separate writer processes. An in-process bounded event buffer can meet that contract. A future out-of-process frontend can reach the same host over a local bridge; it does not inherently require a durable cross-process log. Independent controllers are still outside this architecture.

**INFERENCE — required limits.** After host restart, a cursor whose retained history is unavailable must return CursorExpired and require a fresh snapshot; do not silently accept a bare old revision because it parses. Establish an epoch or validated replay floor tied to the restored workspace revision. Snapshot state and request receipts survive restart; complete event history is not promised. Within an epoch, publication must respect commit order and never drop a previously unpublished lower revision because a later revision arrived first. Replayed original events are not newly committed events and must not cause duplicate publication. Every event in a multi-event commit must remain observable; revision-only cursors require whole-commit delivery/checkpoint semantics, otherwise add an event position to the opaque cursor.

**INFERENCE.** This is a permission to use bounded in-memory history, not acceptance of any particular implementation. The shared suite must exercise two sessions on the same host, commit/publication interleaving, and restart with an old cursor followed by snapshot resynchronization. Revisit durable replay when requirements demand complete history across host restarts, offline consumers that cannot resnapshot, or independent controllers. H101-22's mailbox ordering remains separate.

## H101-75 clarification — canonical inbound records, not a UI exception (2026-09-21)

**CODE-PATH FACT.** The current host.FrontendSession accepts core/task request types for all nine commands. Naming the interface also imports host. Therefore moving presentation into a new package without moving the contract cannot satisfy the existing forbidden-import rule. This is a dependency-shape mismatch, not a reason to weaken the rule.

**INFERENCE — choose option (a).** Put the canonical user-command request records and FrontendSession interface in `internal/api`. That package may depend on context and passive domain values; it must not depend directly or transitively on core/task, host, outbound ports, or concrete adapters. Include all nested request/patch types needed to construct a command. Keep CallerScope, Engine, CommitRequest, delivery recorders, lifecycle and session-binding constructors outside it. IDs, receipts, errors and detached domain results need not be duplicated.

**INFERENCE — avoid translation drift.** Move the existing request definitions rather than copying them into a second schema. Engine methods consume the canonical api types. Temporary compatibility aliases may point **from core/task to api**, never from api back to core/task; they preserve existing callers without making the neutral package depend on the engine. Host may similarly alias the neutral FrontendSession interface for migration, but presentation imports api directly. Aliasing privileged types is forbidden. This is one definition per record, so neither a permanent field-by-field translation layer nor two evolving record sets is required.

**INFERENCE — assembly still needs a home.** Keep a small executable composition root responsible for operator configuration, host.Open, principal binding, and shutdown. Move command parsing/rendering/domain interaction into a presentation package (for example `internal/ui/cli`) whose only application dependency is api plus passive domain records. Inject the actual restricted session wrapper, not broad Capabilities narrowed by an interface. The root may import host; it need not import core/task once requests move. Remove the broad interim presentation exception: any remaining allowlist entry must be narrowly for assembly, with domain command handling absent from that package. A second adapter uses the same api without acquiring a new engine/host exception.

**INFERENCE — why not option (b) alone.** A dedicated translator is valid when deliberately separate transport and domain schemas warrant it. Here it introduces another record set and still needs a neutral UI-facing interface to avoid host imports. Moving the exception while leaving general command handling inside privileged code merely relocates the same problem. Choose a neutral canonical contract now, plus the already-required small composition root; do not choose a translator as a substitute for that contract.

**INFERENCE — implementation and acceptance boundary.** Work is record/interface extraction, imports/aliases, presentation extraction, and gate/tests; no command semantics, persisted schema or outbound port change is intended. Coordinate the mechanical extraction with Kevin's active engine edits rather than parallel-editing that file. The follow-up must demonstrate real CLI and second-adapter presentation imports exclude host/core/task/outbound/storage, api has no transitive privileged dependencies, and forbidden imports fail. Package granularity can enforce this once packages reflect their roles. Review the assembly package for role leakage; a package gate cannot police what privileged code does inside it. Item 4 remains open until that implementation proof lands. No code changed in this ruling.


## H101-94 — generated IDs and uncertainty reconciliation (2026-09-21)

**RULING — ID generation and comparison.** The entity-ID default and optional frontend generation rules are defined in boundaries.md's H101-94 ruling. UI-03's generated-ID recovery obligation applies only when generation occurs; caller-supplied entity IDs need no additional success echo merely to satisfy that clause. Request identity remains mandatory for replay. Canonical scenarios should supply identical IDs or use deterministic allocation. For a scenario explicitly exercising nondeterministic entity generation, extend the canonical-observation normalization rule only for those generated IDs: establish a one-to-one mapping by independently specified creation role and entity kind, preserve repeated references and links throughout receipts/queries/events/replay, and assert each adapter's raw returned ID is the one subsequently used. Never normalize supplied IDs, merge distinct entities, or infer expected state from another adapter's output. Generated-ID recovery after interruption remains a separate obligation; success-response visibility alone does not demonstrate it.

**RULING — uncertainty source.** ADR 0004 supersedes UI-02's older unstructured IOFailure description for uncertain mutation outcomes. Preserve its code, request/workspace identity, effect, confirmation, and optional observed revision in machine-facing output; human-facing output must preserve their meaning and recovery policy. Diagnostic wording is not a semantic branch or conformance assertion. Denied/Conflict coverage does not discharge uncertainty coverage. These rules do not prescribe a fault-injection mechanism or change any workspace-revision arithmetic.


**RULING — H101-94 revision comparison.** Apply boundaries.md's “workspace revision arithmetic and commit groups” ruling to canonical observations: a fresh workspace starts at 0, each new atomic commit group advances once, and mailbox delivery-record groups count. Compare exact numeric revisions at the named equivalent committed cut; never substitute command count, erase revisions, or compare an original receipt with a later snapshot as though they were the same cut. The specified UI-04 final cut has fourteen groups and revision 14. This is a new explicit arithmetic contract; the earlier traceability review correctly found no source for it in the documents then available.
